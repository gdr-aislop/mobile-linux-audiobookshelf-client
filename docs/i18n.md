# Translations

All user-visible text goes through gettext (domain `abs-app`). English is the source language: the
msgid *is* the English text, so an untranslated or missing catalog just shows English.

## Writing code

Use the helpers in `app/src/i18n.rs` — never put a bare literal into a label, title, tooltip, toast…

```rust
use crate::i18n::{ntr_args, tr, tr_args, tr_noop};

label.set_label(&tr("Settings"));
// TRANSLATORS: {server} is the display name of the Audiobookshelf server
row.set_subtitle(&tr_args("Signed in to {server}", &[("server", &name)]));
let text = ntr_args("{count} book in {series}", "{count} books in {series}", n, &[("series", &s)]);
const HEADLINE: &str = tr_noop("Connection lost"); // marked now, translated where shown: tr(HEADLINE)
```

* Placeholders are **named** (`{name}`), never `{}`, so translators can reorder them.
* Plurals use `ntr`/`ntr_args` — don't special-case `n == 1`; other languages have other rules.
  `{count}` is filled in automatically.
* The msgid must be a literal written inside the call. Wrap at the call site, not inside a helper
  that receives a `&str`.
* Not translated: log lines, CSS classes, icon/action/setting names, the product name, and error
  text that comes straight from a library (it is shown under "Show details" as-is).
* `cargo test -p abs-app --test i18n_lint` fails on a bare literal passed to a text setter
  (`.label("…")`, `set_title("…")`, `add_response(id, "…")`, …). If a literal really is not for
  translation, put `// i18n: ignore` on that line.

## Extracting and translating

Needs GNU gettext (`apt install gettext`) and python3.

```sh
scripts/update-pot.sh          # regenerate po/abs-app.pot, merge into po/<lang>.po
msginit -l de -i po/abs-app.pot -o po/de.po     # start a new language
echo de >> po/LINGUAS                           # …and list it, so packaging ships it
```

The template covers the Rust sources, the `.desktop` file and the AppStream metainfo
(`po/gettext-data/its/metainfo.its` tells gettext which metainfo elements are text).

## Packaging

`scripts/build-l10n.sh OUTDIR` compiles every language in `po/LINGUAS` into
`OUTDIR/locale/<lang>/LC_MESSAGES/abs-app.mo` and merges the translations into the `.desktop` and
metainfo files. The AppImage and Flatpak builds call it; for the `.deb`, run
`scripts/build-l10n.sh build/l10n` before `cargo deb` (the release workflow does) and add one
`assets` line per language to `app/Cargo.toml` (an example is in the comment there).

At run time the app looks for catalogs in `$ABS_LOCALEDIR`, else `<exe dir>/../share/locale`, else
`/usr/share/locale` (`i18n::locale_dir`). To try a language from a source build:

```sh
scripts/build-l10n.sh build/l10n
ABS_LOCALEDIR=build/l10n/locale LANGUAGE=de cargo run -p abs-app
```

## Finding missed strings: the pseudo-locale

`scripts/pseudo-locale.py` builds a catalog in which every string reads `[!! original !!]`. Run the
app under it and look at every screen: any English text *without* the brackets was never wrapped
(book titles, server names and other user data are expected to stay plain).

```sh
scripts/update-pot.sh --pot-only
scripts/pseudo-locale.py build/pseudo
ABS_LOCALEDIR=build/pseudo LC_ALL=en_US.UTF-8 LANGUAGE=en cargo run -p abs-app
```
